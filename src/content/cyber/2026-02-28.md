# OSCP Proving Grounds - Fractal

**Author**: [Ayushman Chhabra](/#/blog/author/Ayushman%20Chhabra)

**Published**: 2026-02-28

**Modified**: 2026-06-17

OSCP's PG Fractal lab is one of my favourites. I really enjoyed the process of solving this box. It really sharpened my skills in enumeration, initial access and privileged escalation.

*Please note that only the happy path from enumeration to initial access to privilege escalation is shown and showing all the wrong paths I went down would be too cumbersome.

## Enumeration

Start with an [`nmap`](https://nmap.org/) scan. Observe that port `21` (ftp), `22` (ssh) and `80` (http) are open.

![OSCP Proving Grounds - Fractal 2](2026-02-28_2.png)

Start with port 80 or the webserver. Navigate to `/robots.txt` file. This file sometimes gives important clues, in labs and actual cyber security engagements. Observe that the webserver may be using the PHP framework [`Symfony v3.4`](https://symfony.com/releases/3.4).

![OSCP Proving Grounds - Fractal 3](2026-02-28_3.png)

Go to `/app_dev.php` and observe a panel opens up below which discloses the complete version `v3.4.46`.

![OSCP Proving Grounds - Fractal 4](2026-02-28_4.png)

Moving into the Symfony profiler, it looks like the webserver incorrectly exposes the development endpoint `/app_dev.php` endpoint in production.

![OSCP Proving Grounds - Fractal 5](2026-02-28_5.png)

Now the goal is remote code execution (RCE) via any means necessary. So after some research and the help of the [below article](https://blog.lexfo.fr/symfony-secret-fragment.html), I find that the `_fragment` parameter is vulnerable to RCE.

![OSCP Proving Grounds - Fractal 7](2026-02-28_7.png)

Every URL has to be signed with a secret. A common misconfiguration is the secret is a [common/default value](https://www.invicti.com/web-application-vulnerabilities/symfony-rce-via-weak-predictable-app-secret) and can be easily guessed or can be accessed via a file read vulnerability through a security misconfiguration. In our case, its the latter.

![OSCP Proving Grounds - Fractal 6](2026-02-28_6.png)

With the help of the [symfony-exploits](https://github.com/ayushmanchhabra/symfony-exploits), I create a URL which calls the `phpinfo()` function to test if the signed URL works correctly.

![OSCP Proving Grounds - Fractal 8](2026-02-28_8.png)

Once I have confirmed the URL is signed properly, I naturally try to execute the `system()` function but run into a 500 Internal Server error.

![OSCP Proving Grounds - Fractal 9](2026-02-28_9.png)

I realise that the [`system()`](https://www.php.net/manual/en/function.system.php) function takes two variables and due to the limitations of the Python exploit code, I am unable to input the second argument. After going through the article again, I try another method where I directly call a Symfony library function via the URL through which I call the `system()` function again but this time with parameter id. Although the server returns another 500 Internal Server error, we are able to confirm RCE by observing the user and group names!

![OSCP Proving Grounds - Fractal 10](2026-02-28_10.png)

The next step is finding the reverse shell script that works.

![OSCP Proving Grounds - Fractal 11](2026-02-28_11.png)

## Initial Access

After a few trial and errors, I am able to get shell access. Notice the `mysql`, `proftpd`, `ftp` and `benoit` users since they will be recurring in the steps below.

![OSCP Proving Grounds - Fractal 12](2026-02-28_12.png)

At this point I am in a restricted shell environment. I want to get access to a privileged user. Lets explore `/etc/proftpd`, see if it is accessible and how it is configured. On listing the files and directories and going through them one by one, we see some interesting information inside `sql.conf`. It looks like the SQL database is used to CRUD FTP user information.

![OSCP Proving Grounds - Fractal 13](2026-02-28_13.png)

I log into the SQL service using the discovered credentials and observe that the FTP users are stored in the `ftpuser` table in `proftpd` database.

![OSCP Proving Grounds - Fractal 14](2026-02-28_14.png)

Since the password is hashed using MD5 and I have write access to the database, I simply insert an MD5 hash of `password`.

![OSCP Proving Grounds - Fractal 15](2026-02-28_15.png)

Using a SQL query I update the `benoit` (id=2) user's properties such as UID, GUID, shell, homedir, etc.

![OSCP Proving Grounds - Fractal 16](2026-02-28_16.png)

I create a SSH keypair using [`ssh-keygen`](https://linux.die.net/man/1/ssh-keygen).

![OSCP Proving Grounds - Fractal 17](2026-02-28_17.png)

I log into FTP service using user `benoit` (id=2) whose properties I changed earlier. I add my public key to the target host's `authorized_keys`.

![OSCP Proving Grounds - Fractal 18](2026-02-28_18.png)

## Privelege Escalation

Finally I simply log in via SSH as `benoit` and observe that the user either has a misconfigured `sudo` or has been added to the `sudoers` list. Privilege escalation is as simple as `sudo su`.

![OSCP Proving Grounds - Fractal 19](2026-02-28_19.png)

## Closing Remarks

Fractal was the first lab I did when I started preparing for OSCP. It took me an absurd amount of time to complete but it taught me that always give attention to detail and enumerate everything (before _and_ after gaining initial access). You will find root when you least expect it.
